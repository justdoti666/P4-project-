## 1. 高优先级

### H1 · 画布不认 P2 的 `sid` 字段（实测会抛异常）

- **处理**：`ui/canvas.py::_as_station_id` 增加 `sid`（以及字典形式 stations 的 key 回退）。
- **证据**：`tests/test_contracts.py::CanvasCompatTests::test_graph_accepts_sid_field`
  用 `Station(sid, name, x, y)` 风格的假对象验证 `normalise_graph()` 成功；
  `test_graph_dict_stations_falls_back_to_key` 验证 `{"S1": 无 id 对象}` 也能画。
- **说明**：本次只做“读兼容”，不修改 `core` 的字段名；P1/P2 合并时零改动。

### H2 · `events` 的 `(kind, sid)` 写法被误解析（动画静默失效）

- **处理**：新增 `_as_event_station`：先判 `kind ∈ {settle,visit,push,pop,…}` 再取第二项；
  否则按站台节点元组取第一项。`normalise_result` 改用它，docstring 同步澄清。
- **证据**：`test_events_accept_kind_sid_tuples`（`("settle","S1")`）、
  `test_events_accept_dicts_and_plain_ids`（`{"kind":…,"sid":…}`、纯 ID、`("S3","L1")`）
  三条测试覆盖；旧写法（纯 ID / 站台元组）行为不变。

## 2. 中优先级

### M1 · 缺少距离权重 / 无法表达快线（任务书 P01 缺口）

- **处理（代码落地，非仅文档）**：
  - `core/graph.py`：`MetroLine.speed_kmh` 可选字段；`line_speed()` / `max_speed_kmh()`；
    Dijkstra/A* 边权按 `weight` 取时间或距离；距离权重下 A* 启发函数改用直线距离；
    A* 时间权重启发函数改用 `max_speed_kmh()`，有快线时仍可采纳。
  - `core/algorithms.py`：`normalise_weight()`（time/distance + 中文别名）、
    `dijkstra/astar/bfs_min_transfers/solve/compare_algorithms` 全部支持 `weight`；
    `RouteResult.weight` 记录口径。
  - `metro_api.py`：`route(..., weight=)`、`compare(..., weight=)`、CLI `--weight`、
    HTTP `weight` 查询/请求体全链路；版本号 1.1.0。
  - 报告第 1.4 / 3.1 / 3.2 / 5.2 / 5.4 节补“双权重 + per-line 速度”的口径，
    并给出 S001→S061 的实例：最快 79.6 min / 33.24 km vs 最短里程 82.3 min / 33.22 km。
- **证据**：`tests/test_contracts.py::WeightTests`（4 条：时间/距离最优性、A* 与 Dijkstra
  在两种权重下同优、中文别名、BFS 权重与 visited_order）；`selfcheck.py` 第 04 项新增
  距离权重断言（`main.py --check` 实时验证）；API 测试新增 6 条 weight 用例。
- **兼容性**：默认 `weight="time"`，所有旧调用/报告数值/bench 结果完全不变（已回归）。

### M2 · BFS 的 `expanded` / `visited_order` 与最终路径不同源

- **处理**：
  - `expanded` 保持“分层 BFS 线路扩展帧”的真实含义，不再被误用为可横比指标：
    代码 docstring、报告 4.6 表注、自检说明、`docs/bench.md` 均写明“口径不同、不横比”；
  - **动画顺序**改为使用第二阶段（决定最终路径）的 `visited_order`，只有第二遍没有
    记录时才回退分层 BFS 层序，保证“搜索波”与高亮路径同源；
  - 报告 4.6 结论（1）明确“扩展最少”只针对 Dijkstra/A* 两种逐站台算法。
- **证据**：`WeightTests::test_bfs_weight_and_visited_order` 断言 `visited_order` 非空且
  从起点开始；`bench.py` 的图注与 summaries 同步改为“BFS 不参与横比”。

### M3 · 报告结论与自身数据矛盾（“A* 平均搜索规模最小”）

- **处理**：源句在 `docs/bench.md` 的自动摘要里；已改为“A* 在 **Dijkstra/A* 两种逐站台
  算法**中扩展最少；BFS 的数字是线路扩展帧，口径不同，不参与横比”。`tools/bench.py`
  的 `summaries()` 同步修改；报告 4.6 结论（1）与 5.2 效率段同步加限定语。
- **证据**：`docs/bench.md` 对应行已改；重新生成的 docx 中不再出现“平均搜索规模最小”
  （`tools/check_report.py` 22/22 绿）。

### M4 · `tools/bench.py` 默认覆盖入库产物，复跑即让报告闸门变红
