## 2. 五条验收逐项证据

### 验收 1：任意窗口尺寸下不变形、不裁切、站名不重叠

**怎么验**

```powershell
python tools/export_canvas.py docs/figures/demo_1200.png --demo --width 1200 --height 800
python tools/export_canvas.py docs/figures/beijing_1400.png --width 1400 --height 900
python main.py --smoke _smoke/window_1070.png    # 实际窗口约 1070×700 的截图
python selfcheck.py --only 10                    # 站名两两重叠检查
```

**看到什么算过**

* `ViewTransform` 用 `min(可用宽/世界宽, 可用高/世界高)` 求同一个比例，x/y 同比例；
* 10 站演示图在 1200×800 下 **10/10 站名、5/5 分段标注**，两两零重叠（自检第 10 项）；
* 134 站北京图在 1400×900 下画出 **121 个站名**，两两零重叠；放不下的 13 个省略，
  放大后可恢复，不会互相压盖；
* 三种尺寸的导出图见 `docs/figures/` 与 `_smoke/`。

![10 站演示路径](figures/fig_p4_demo_path.png)

![134 站北京路径](figures/fig_p4_beijing_path.png)

> 说明：密集图不能既“全部显示”又“零重叠”，本项目选择保证零重叠、按优先级省略，

### 验收 2：缩放、平移、悬停、缩放后点击命中

**怎么验**

```powershell
python main.py --check --verbose      # 第 09 项：坐标数学；第 10 项：真实画布交互
```

**看到什么算过**

* 第 09 项：y 翻转、等比、屏幕↔世界往返误差 <1e-6、以光标为锚点缩放、0.5–3× 限幅；
* 第 10 项：缩放 2.5× + 平移后，对 10 个站分别点在圆心和偏 11px 的位置，
  都命中同一个站，命中误差 11.0px ≤ 12px；
* 拖拽：模拟按下→拖 40px/20px→松开，地图整体移动 40/20px，图例位置不变；
* 手工：滚轮放大到 3× 后点击站点仍能选中（见录屏脚本 1:40 处）。

### 验收 3：动画逐帧、调速、暂停/跳过，动画与立即数值一致

**怎么验**

```powershell
python main.py
# 选「苹果园 → 天通苑北」，先点“搜索”，再点“动画”，中途点“暂停”“继续”“跳过”
python selfcheck.py --only 10 --verbose
```

**看到什么算过**

* `animate()` 返回的统计字典与 `show_path()` **逐键相等**（自检第 10 项直接比较）；
* 动画只改变“画到第几个站/第几段”，所有数值在动画开始前由同一个 `PathView` 确定；
* 1×/2×/4× 通过定时器间隔换算（30ms、80ms 两档除以速度），不会 `sleep` 阻塞界面；
* 暂停 = 取消定时器且不排下一帧；继续 = 再排一帧；跳过 = 直接落到最终静态图；
* 切换算法/重新搜索时先 `after_cancel` 旧任务并删 `anim` 图层，
  自检断言 `find_withtag("anim") == ()`；
* 过程录屏：仓库已带 [`P4-演示动画.gif`](P4-演示动画.gif)，由 `tools/record_demo.py` 自动录制。

## 3. 接口交接（给 P3）

```python
from ui.canvas import CanvasView

# 1) 嵌进你的容器（不要自己再建 Canvas）
self.canvas = CanvasView(self.map_frame, graph)
self.canvas.pack(fill="both", expand=True)

# 2) 点击站点
self.canvas.bind_click(self.on_station_clicked)   # callback(sid: str)

# 3) 搜索结果
self.canvas.show_path(result)                     # 静态
self.canvas.animate(result, speed_level=2)        # 动画
self.canvas.reset()                               # 复位

# 4) 导出
self.canvas.export(r"_smoke\result.png")
```

### 行为约定

| 场景 | 画布行为 |
| --- | --- |
| 传入 `result=None` | 显示“还没有搜索”，不抛异常 |
| `found=False` | 左上角红色「未找到路径」卡片，不画路径 |
| 起终点相同 | 画一个紫色「起终」徽标，统计 0 分钟 |
| 搜索中切算法 | 自动取消旧动画，只保留新结果 |
| 窗口缩到很小 | 隐藏图例/信息卡，站名按空间省略，不重叠 |
| 反复 `show_path` | 覆盖旧路径，不残留标签 |

### 不要做的事

* 不要在 P3 里直接 `canvas.create_*` 画业务图形，所有绘制走 `CanvasView`；
* 不要修改 `canvas.draw_graph` / `canvas._transform` 的私有状态；
* 不要在创建 Tk 前忘记 `ui.dpi.enable_high_dpi()`（导出 PNG 才需要，工具已内置）。

### 给全班 / 外部程序调用（P4 扩展）

除画布外，P4 还提供一层**不打开窗口**的调用接口，与界面共用同一份 `core.solve`：

```python
from metro_api import connect

nav = connect()                                    # 无 Tk、零第三方依赖
print(nav.route("苹果园", "天通苑北")["summary"])    # 79.575 min / 33.236 km / 换乘 1
print(nav.compare("慈寿寺", "崇文门")["highlights"]) # BFS 少 1 次换乘、多花约 2.6 min
```

```powershell
python metro_api.py route --start S001 --end S061 --json
python tools/serve_api.py --port 8765              # HTTP：GET /api/route?start=..&end=..
python -m unittest discover -s tests -v            # 接口回归（34 用例）
```

方法与 JSON 结构、HTTP 端点、错误码见 [`API接口说明.md`](API接口说明.md)。

## 4. 性能与观感数据

测试环境：Windows 11、Python 3.12.14、Tk 8.6、1400×900 画布、134 站 7 线。

| 动作 | 实测 | 做法 |
| --- | --- | --- |
| 首次加载 + 绘制 | 约 200ms（含首次字体测量） | 一次性画完 |
| 平移（拖拽） | 每帧数毫秒 | 只 `canvas.move` 图元，不重排文字 |
| 滚轮缩放一次 | 约 80ms | 合并 16ms 内的重绘请求 |
| 动画 tick | <10ms | 只删/画 `anim` 图层 |
| 导出 PNG | 约 3s（含 0.35s 等待窗口合成） | 先 DPI 感知再截图 |

文字缓存：134 个站名的宽度只量一次，避免每帧调用 Tk 字体测量；
站名排版用 64px 网格索引，只检查附近矩形。

## 6. 已知限制（写进报告 5.4）

1. 密集图自动省略部分站名/分段标注；这是“零重叠”与“信息全显示”之间的取舍；
2. PNG 导出是屏幕截图，要求窗口可见；PS 是矢量，适合印刷但 Windows 不预览 EPS；
3. BFS 的 `expanded` 按线路扩展，和 Dijkstra/A* 的逐站台计数口径不同，
   对比实验以 A* vs Dijkstra 为主；
4. 坐标是教学示意坐标，没有做真实地图投影；
5. 仓库已带自动录制的 [`P4-演示动画.gif`](P4-演示动画.gif)（真实窗口、23 帧）；
   正式 2 分钟 mp4 仍建议按 [`P4-演示录屏脚本.md`](P4-演示录屏脚本.md) 人工录，
   或安装 ffmpeg 后运行 `python tools/record_demo.py --mp4 输出.mp4`。
